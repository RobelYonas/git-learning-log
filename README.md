### Understanding git add vs git commit

git add adds the file to the staging area, which is the process of selecting specific changes. Git commit records the changes with a message attached.

## Branching and Working in Parallel

### Creating and switching branches

In this step, I will create a new branch and switch to it.  So that I can make commits in the new branch and understand how to handle merge conflicts when merging back into the main branch.

![Image](https://nextwork.ai/courageous_navy_vibrant_blackcurrant/uploads/8bf3bcb5-a70d-418a-9c76-251365f69028_drz4zcda)

### Why merge conflicts occur

A merge conflict happens because the same file has been changed in two different branches. Because of that, when merging both files and their changes, a conflict occurs.

## Merging Branches and Resolving Conflicts

### Merging feature branches into main

In this step, I'm merging two branches that modified the same file. So that I can read and understand the git conflict markers, resolve the conflict, and complete the merge commit.

### Interpreting Git conflict markers

The conflict markers show me the current and incoming changes, and they allow me to modify them as needed for my final file. 

## Publishing to GitHub

### Creating a remote repository

In this step, I'm setting up a public GitHub repository to push my local repository and verify that my commit history and branches are visible online.

![Image](https://nextwork.ai/courageous_navy_vibrant_blackcurrant/uploads/8bf3bcb5-a70d-418a-9c76-251365f69028_l5jsusg6)

### Pushing local commits to GitHub

git push uploads your local code to a server like GitHub. You need a "remote" first to give Git the destination web address; otherwise, it doesn't know where to send your files.
